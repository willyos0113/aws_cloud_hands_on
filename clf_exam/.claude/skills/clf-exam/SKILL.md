# clf_exam 出題與評估規範

此規範由 `clf_exam/` 內現有檔案（第一回 PDF、1020、1021、弱點專項各卷與結果檔、`學習評估.md`）歸納。**只管這個資料夾**。

動手前先讀：最新一份 `*_答案卷.md`（格式範本）、全部 `*_測驗結果.md`（找弱點）、`學習評估.md`（目前的診斷與待辦）。

## 1. 資料夾與檔案類型

| 位置 | 內容 | 規則 |
| ---- | ---- | ---- |
| `meterials/` | 教材 PDF：D05～D11 題庫練習、CLF-C02 2026Q3 教材 | 只讀的來源。資料夾名 `meterials` 是既有拼法，**不要改成 materials** |
| `questions/` | 各回題目卷、答案卷、測驗結果 | 新檔都放這裡 |
| `學習評估.md` | 歷次成績與診斷紀錄 | 往下追加日期段落，不覆寫舊評估 |

教材是第三方販售內容。新增教材 PDF 前，先確認 repo 是否公開，公開就提醒使用者。

## 2. 檔名規則

| 類型 | 檔名 |
| ---- | ---- |
| 整回題目卷／答案卷 | `clfc02_MMDD_題目卷.md`、`clfc02_MMDD_答案卷.md`（各附同名 `.pdf`） |
| 同一天第二份以上 | `clfc02_MMDD_2_主題_題目卷.md`（例：`clfc02_1021_2_弱點專項_題目卷.md`），答案卷同前綴 |
| 測驗結果（使用者填寫） | 與題目卷同前綴：`clfc02_MMDD_測驗結果.md` |
| 第一回（舊命名，不再沿用） | `CLF-C02_100題_題目卷.pdf`、`CLF-C02_測驗結果.md` |

- `.pdf` 由使用者轉出，不自己宣稱已產生。
- 題目卷內「作答完再對照 `xxx_答案卷.md`」的檔名，必須與實際檔名一致。重新命名檔案後要同步更新。

## 3. 題目卷格式

```
# CLF-C02 模擬練習題（第N回・題目卷）        ← 弱點專項：# CLF-C02 弱點專項測驗（題目卷）

AWS Certified Cloud Practitioner (CLF-C02) … · 共 N 題（單選 X 題、複選 Y 題）· 出題依據與範圍

> 標示「選兩項」者為複選，其餘為單選。作答完再對照 `…_答案卷.md`。

## 章節名稱（N 題）          ← 弱點專項用「一、二、三」中文編號

**1.** 題目
- (A) …
- (B) …
```

- 題號全卷連續，不按章節重編。
- 單選 4 個選項；複選 5 個選項，題目結尾標 `（選兩項）`。整回單選：複選約 88：12。
- 題目寫情境與需求訊號詞，不直接講出服務名稱。限定詞（成本最低、不需額外費用、同步／非同步、既有授權）要寫進題目。

## 4. 答案卷格式

```
# CLF-C02 … （答案卷）

## 答案速查            ← 弱點專項用 3 欄表（題號｜答案 ×3）；整回不強制

## 詳解

## 章節名稱

**N.** 答案：**X**

一兩句說明為什麼對。
易混淆：最容易選錯的選項為什麼不對。

👉 一行口訣：需求訊號詞 -> 服務。
```

- 整回題目另加一行 `> 出處：D06 · 題庫第 0254 題`，改寫題標 `（本題為改寫，非原題）`，延伸題標 `延伸（主題）`。弱點專項不放出處行。
- `易混淆` 這行**必寫**，這是弱點專項的核心價值。多個誘答選項時挑最常被誤選的。
- 口訣用「訊號詞 -> 答案」，有對照的概念寫成分界線，例如「同步、容錯移轉 -> Multi-AZ；非同步、分攤讀取 -> Replica」。

## 5. 出題原則

1. **不與既有各卷重複**：出題前掃過所有 `*_題目卷.md`，同一個考點可以再考，換情境與說法。
2. **不出答案有爭議的題目**。教材題庫與實務不同時（例如 IAM User vs Identity Center），在解析註明「考試照題庫答」。
3. **誘答選項要有鑑別力**：用同類服務當誘答（Route 53／CloudFront／Global Accelerator，Multi-AZ／Read Replica），不要放明顯無關的選項。
4. **答案位置分散**：避免連續三題同一字母，A～D 大致均勻。
5. **數字與定價不確定時**，寫「待查證」或不出該題，不憑記憶寫。2 分鐘 Spot 警告、Glacier 取回時間這類寫進解析前先對照教材。
6. **考試背景**：CLF-C02 共 65 題（含不計分題）、90 分鐘、1000 分制 700 分及格。四大領域為雲端概念、安全與合規、雲端技術與服務、帳單／計價／支援，權重以 AWS 官方考試指南為準，整回題目照此比例分配。
7. **弱點專項**：只選歷次結果裡錯 2 次以上的主題；已連續全對的主題先不出。題數 15～30，章節名稱照主題。

## 6. 測驗結果檔怎麼讀

結果檔結構：

```
# 標題
## 詳解
**N.** 答案：**X**
👉 使用者自己寫的筆記
## 測驗結果
分數: 總題數/答對題數        ← 例：100/76 = 100 題答對 76
花費時間 / 時間: …
```

- **只列答錯的題目**。錯題數 = 檔內題號數量，可與「總題數 − 答對題數」互相核對。
- `分數` 欄的順序是「總題數／答對題數」。算正確率時別弄反。
- 缺分數或時間時，用錯題數推算並**明講是推算**，請使用者之後補上。
- **使用者的 `👉` 筆記是他們自己的**：保留，不潤飾。發現事實錯誤或錯字時，指出來，不擅自改檔。
- 「使用者選了哪個選項」結果檔沒有記錄。只能從筆記推測，推測時要明講。

## 7. 評估流程

1. 讀全部結果檔，統計每個主題的錯題數與重複出現的題型。
2. 與前幾回比：答對數、正確率、作答時間。一併檢查「時間變短、分數沒變」是否表示漏看限定詞。
3. 分成「已穩定」「仍在錯」，並列出**易混淆配對**（例如 Multi-AZ 與 Read Replica）。
4. 提醒限制：弱點專項題數少、題目針對弱項出，正確率不能代表整體實力；700/1000 不能直接換算成百分比。要看整體進步，要再做一整回新題。
5. 給下一步：重做時間（隔天、第 3 天、第 7 天）、下一輪範圍。
6. 使用者要求時，把評估追加到 `學習評估.md`（日期＋成績總覽＋診斷＋下一步），不覆寫舊內容。

## 8. 新增後的收尾

1. 確認新題目卷與答案卷的檔名、交叉引用、題數與單選／複選數量一致。
2. 答案速查表與詳解的答案完全一致，逐題核對。
3. `README.md` 的 `clf_exam/` 段落若描述過時（目前只寫 100 題 PDF），提醒使用者更新或在要求時一併修改。
4. 不自動 commit 或 push，使用者要求時才提交。
