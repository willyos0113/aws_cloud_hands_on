### 2. 學習方式上的問題

1. **筆記是「關鍵字 → 答案」。** 例如「短時間可中斷 → Spot」，題目換個說法就失效。更有用的是記下「為什麼其他選項不對」以及兩個服務的分界線。
2. **作答時間從 44 分降到 27 分，分數沒有跟著上升。** 100 題 27 分鐘平均不到 17 秒一題，可能漏看了「成本最低」、「不需額外費用」、「同步／非同步」這類限定詞。這是從錯題解析推測的，沒有作答紀錄可以確認。真正的考試是 65 題、90 分鐘，每題有 80 多秒。
3. **每回題目不重複**，所以分數反映的是整體覆蓋度，看不出修正過的觀念有沒有學會。

### 3. 建議的做法

- 把錯題整理成「易混淆對照表」：一組概念一個表格，欄位寫「判斷關鍵詞」與「容易誤選的原因」。
- 改成按主題做小考（15～20 題），隔天、第 3 天、第 7 天各重測一次。
- 做題時先圈出限定詞再看選項，速度放慢到每題 45～60 秒。
- 筆記多記「為什麼不選其他選項」。
- 下一回刻意重考已錯過的概念，用新題目但考同樣觀念，才看得出進步。

## 三、單題補充說明：弱點專項第 9 題為何不是 Trusted Advisor

題目：評估組織上雲的準備度、找出人員與流程缺口、規劃整體轉型。答案是 **Cloud Adoption Framework（CAF）**。

|                          | 檢查什麼                                                  | 對象     |
| ------------------------ | --------------------------------------------------------- | -------- |
| Trusted Advisor          | 帳戶裡現有的 AWS 資源（成本、安全、容錯、效能、服務配額） | 資源     |
| Cloud Adoption Framework | 組織上雲的準備度（人員、流程、治理等六個視角）            | 組織     |
| Well-Architected Tool    | 單一工作負載的架構檢視與評分                              | 工作負載 |

- 題目的「組織」、「人員」、「流程」都是 CAF 的範圍；Trusted Advisor 看不到人員技能與組織流程。
- 判斷：看到「資源／帳戶的檢查建議」答 Trusted Advisor；「組織轉型／準備度」答 CAF；「單一工作負載的架構檢視」答 Well-Architected。
- 這題的選項是從使用者的提問推測選了 Trusted Advisor，結果檔沒有記錄實際選項。
