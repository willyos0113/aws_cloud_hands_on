## 二、RDS 與 Aurora（6 題）

**11.** 公司的訂單資料庫在主要資料庫發生故障時，需要自動切換到另一個可用區域的備援，且已確認的交易資料不能遺失。應該使用什麼？

- (A) RDS Multi-AZ 部署
- (B) RDS Read Replica
- (C) 手動快照
- (D) 擴大資料庫執行個體規格

**12.** 每月結算期間，大量報表查詢拖慢了主資料庫，公司想把讀取流量分流出去。應該使用什麼？

- (A) RDS Multi-AZ 部署
- (B) RDS Read Replica
- (C) 自動備份
- (D) 增加儲存空間

**13.** 營運團隊希望報表查詢不要影響交易系統，同時主資料庫故障時能自動容錯移轉。應該怎麼設定？

- (A) 只啟用 Multi-AZ
- (B) 只建立 Read Replica
- (C) 啟用 Multi-AZ，並另外建立 Read Replica
- (D) 每天建立手動快照

**14.** 關於 RDS Read Replica，下列哪兩項敘述是正確的？（選兩項）

- (A) 與主資料庫之間是非同步複寫
- (B) 主要目的是在故障時自動容錯移轉
- (C) 可以分攤讀取流量
- (D) 與主資料庫之間是同步複寫
- (E) 平時不處理任何流量，只是待命

**15.** 開發測試用的資料庫，大部分時間閒置，用量又難以預測，公司希望容量能自動調整，並避免為閒置時段付費。應該選哪一項？

- (A) 啟用 Multi-AZ 的 RDS
- (B) 建立 Read Replica
- (C) 固定規格的大型 RDS 執行個體
- (D) Amazon Aurora Serverless

**16.** 公司需要在誤刪資料後，能把資料庫還原到過去某個時間點。應該使用什麼？

- (A) RDS 自動備份（搭配時間點還原）
- (B) RDS Multi-AZ 部署
- (C) RDS Read Replica
- (D) 加大資料庫執行個體

## 三、DNS、CDN 與負載平衡的分工（8 題）

**17.** 公司在多個 Region 各部署一組應用程式，希望透過 DNS 依延遲把使用者導向反應最快的 Region。應該使用什麼？

- (A) Amazon CloudFront
- (B) Amazon Route 53 延遲路由（latency-based routing）
- (C) Application Load Balancer
- (D) S3 Transfer Acceleration

**18.** 網站有大量圖片與影片等靜態內容，希望使用者從離自己最近的邊緣節點取得，以降低延遲。應該使用什麼？

- (A) Amazon Route 53
- (B) AWS Global Accelerator
- (C) Amazon CloudFront
- (D) Elastic Load Balancing

**19.** 線上遊戲使用 TCP 與 UDP 流量，需要固定的 Anycast IP，並希望流量走 AWS 全球骨幹網路，導向最近且健康的端點。應該使用什麼？

- (A) Amazon CloudFront
- (B) Amazon Route 53
- (C) Network Load Balancer
- (D) AWS Global Accelerator

**20.** 公司希望依 URL 路徑（例如 `/api` 與 `/images`）把 HTTP 請求分別導向不同的目標群組。應該使用什麼？

- (D) Amazon Route 53

**21.** 應用程式需要處理極高流量的 TCP 與 UDP 連線，要求極低延遲，並且需要每個 AZ 一個固定的靜態 IP。應該使用什麼？

- (A) Network Load Balancer
- (B) Application Load Balancer
- (C) Auto Scaling
- (D) Amazon CloudFront

**22.** 促銷活動期間，網站的 EC2 CPU 使用率持續飆高。公司希望自動增加執行個體數量，活動結束後再自動減少。應該使用什麼？

- (A) Application Load Balancer
- (B) Amazon EC2 Auto Scaling
- (C) Amazon Route 53
- (D) AWS Global Accelerator

**23.** 下列哪兩項可以用來做跨 Region 的容錯移轉？（選兩項）

- (A) Amazon Route 53 容錯移轉路由（搭配健康檢查）
- (B) Application Load Balancer
- (C) AWS Global Accelerator
- (D) S3 Transfer Acceleration
- (E) Amazon EC2 Auto Scaling

**24.** 公司發布新版本時，想用 DNS 先讓 20% 的流量到新版本、80% 仍到舊版本，再逐步調整比例。應該使用 Route 53 的哪一種路由政策？
