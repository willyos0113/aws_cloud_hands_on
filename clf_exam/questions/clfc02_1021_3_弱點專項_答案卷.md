## 詳解

## 一、Well-Architected 與 Cloud Adoption Framework

**1.** 答案：**A**

「小幅度、可回復的頻繁變更」與「以程式碼執行營運」都是營運卓越的設計原則。
易混淆：可靠性談的是從故障中復原與容量規劃；成本最佳化談的是消除浪費。

👉 營運用程式碼、小步變更、持續改善流程 -> 營運卓越。

**2.** 答案：**D**

「不猜容量、水平擴展、自動從故障復原」是可靠性的設計原則。
易混淆：效能效率談的是選對資源類型與評估新技術；營運卓越談的是營運流程與變更方式。

👉 自動復原、水平擴展、不猜容量 -> 可靠性。

**3.** 答案：**A**

定期評估新服務、無伺服器架構與更適合的運算類型，是效能效率的設計原則。
易混淆：成本最佳化是消除浪費，不是選對資源類型；營運卓越是流程面。

👉 選對資源類型、持續評估新技術 -> 效能效率。

**4.** 答案：**B**

「操作可追蹤（CloudTrail）、每一層都有安全控制、讓人遠離資料」都是安全支柱的設計原則。
易混淆：營運卓越也會提到紀錄，但重點是營運流程的改善，不是存取控制與資料保護。

👉 可追溯、分層防禦、保護資料 -> 安全。

**5.** 答案：**AB**

採用用量計費的消費模式、分析並歸因支出，都是成本最佳化的設計原則。
易混淆：自動復原與測試復原程序屬於可靠性；以程式碼執行營運屬於營運卓越。

👉 用量計費、支出歸因、不花在非差異化的雜務上 -> 成本最佳化。

**6.** 答案：**B**

提高資源使用率、使用受管服務、減少對環境的衝擊，是永續性的設計原則。
易混淆：提高使用率也能省錢，所以容易選成本最佳化；但題目的目的是降低環境衝擊，不是降低費用。

👉 環境衝擊、使用率、受管服務 -> 永續性；省錢 -> 成本最佳化。

**7.** 答案：**B**

員工訓練、組織文化、人才招募與組織設計，是 People 視角的範圍。
易混淆：Governance 管的是計畫與投資組合管理、風險與雲端財務管理，不是人員能力。

👉 人員、訓練、文化 -> People；投資組合、風險、財務治理 -> Governance。

**8.** 答案：**C**

讓雲端投資與業務策略一致、建立 business case，是 Business 視角的範圍。
易混淆：Governance 偏重管控與財務管理的做法，Business 才是「為什麼要上雲、對業務的價值」。

👉 業務策略、business case、價值 -> Business。

**9.** 答案：**D**

事件管理、可觀測性、變更管理屬於 Operations 視角。
易混淆：Platform 視角是建置雲端平台、架構與資料；Security 視角是安全控制與合規。

👉 CAF 六個視角：Business、People、Governance、Platform、Security、Operations。

**10.** 答案：**AC**

六大支柱是營運卓越、安全、可靠性、效能效率、成本最佳化、永續性。
易混淆：敏捷性、可擴充性、合規性都不是支柱，它們聽起來像雲端優勢，但不在 Well-Architected 的六大支柱內。

👉 六大支柱：營運卓越、安全、可靠、效能、成本、永續。

## 二、RDS 與 Aurora

**11.** 答案：**A**

「故障時自動切換到另一個 AZ、資料不遺失」是 Multi-AZ 的目的：同步複寫到備援，故障時自動容錯移轉。
易混淆：Read Replica 是非同步複寫，主要用來分攤讀取，可能有延遲，不以容錯移轉為主要目的。

👉 同步複寫、自動容錯移轉、高可用 -> Multi-AZ。

**12.** 答案：**B**

把讀取流量分流出去，要用 Read Replica。
易混淆：Multi-AZ 的備援執行個體平時不處理讀取流量，加了也無法分擔報表查詢。

👉 分攤讀取、擴展讀取效能 -> Read Replica。

**13.** 答案：**C**

兩個需求不同：分流讀取靠 Read Replica，自動容錯移轉靠 Multi-AZ，兩者可以同時使用。
易混淆：只用其中一個，只能滿足一半的需求。

👉 Multi-AZ 管可用性，Read Replica 管讀取效能，兩者是互補，不是二選一。

**14.** 答案：**AC**

Read Replica 與主資料庫之間是非同步複寫，用途是分攤讀取流量。
易混淆：「同步複寫」與「為容錯移轉而生」是 Multi-AZ 的特性；「待命、平時不處理流量」是 Multi-AZ 備援執行個體的樣子。

👉 Read Replica：非同步、分攤讀取；Multi-AZ：同步、高可用。

**15.** 答案：**D**

Aurora Serverless 會依負載自動調整容量，閒置時縮到很小，適合用量不可預測或間歇性的工作負載。
易混淆：Multi-AZ 與 Read Replica 都是高可用／讀取擴展，不會讓容量隨負載自動伸縮；固定規格的大型執行個體閒置時仍然全額計費。

👉 用量不可預測、閒置多、自動調整容量 -> Aurora Serverless。

**16.** 答案：**A**

RDS 自動備份搭配交易日誌，可以還原到保留期間內的任一時間點。
易混淆：Multi-AZ 的備援資料是同步的，誤刪的操作也會同步過去，所以不是備份；Read Replica 同理。

👉 還原到過去時間點 -> 備份；Multi-AZ 與 Replica 都不是備份。

## 三、DNS、CDN 與負載平衡的分工

**17.** 答案：**B**

Route 53 延遲路由在 DNS 層依延遲把使用者導向反應最快的 Region。
易混淆：CloudFront 是內容快取的 CDN；ALB 只存在於單一 Region；S3 Transfer Acceleration 是加速上傳到 S3。

👉 DNS 層、依延遲選 Region -> Route 53 latency routing。

**18.** 答案：**C**

靜態內容快取到離使用者最近的邊緣節點，是 CloudFront 的工作。
易混淆：Global Accelerator 不快取內容，它是把流量走 AWS 骨幹網路導向最近的端點；Route 53 只做 DNS 解析。

👉 快取內容、邊緣節點 -> CloudFront；不快取、固定 IP、走骨幹網路 -> Global Accelerator。

**19.** 答案：**D**

TCP／UDP 流量、固定 Anycast IP、走 AWS 全球網路導向最近健康端點，是 Global Accelerator。
易混淆：NLB 也處理 TCP／UDP，但只在單一 Region 內，不是全球；CloudFront 針對 HTTP(S) 內容快取。

👉 Anycast 靜態 IP、跨 Region、非 HTTP 也行 -> Global Accelerator。

**20.** 答案：**A**

依 URL 路徑、主機名稱、標頭等第七層（HTTP）條件路由，是 ALB 的功能。
易混淆：NLB 在第四層，看不到 URL 路徑；Gateway Load Balancer 是用來掛第三方網路設備；Route 53 在 DNS 層，看不到 URL 路徑。

👉 看得到 HTTP 路徑／標頭 -> ALB（第七層）。

**21.** 答案：**A**

極高效能、極低延遲的 TCP／UDP 流量，加上每個 AZ 可有固定的靜態 IP，是 NLB。
易混淆：ALB 是第七層、功能多但沒有固定 IP；Auto Scaling 管數量，不是分流。

👉 第四層、超高效能、靜態 IP -> NLB；第七層、依內容路由 -> ALB。

**22.** 答案：**B**

依指標自動增減執行個體數量，是 EC2 Auto Scaling 的工作。
易混淆：ALB 只負責把流量分給現有的執行個體，不會增減數量。

👉 增減執行個體數量 -> Auto Scaling；把流量分給執行個體 -> ELB。

**23.** 答案：**AC**

Route 53 容錯移轉路由（搭配健康檢查）與 Global Accelerator 都能在一個 Region 異常時，把流量導向另一個 Region。
易混淆：ALB 和 Auto Scaling 都只在單一 Region 內運作；S3 Transfer Acceleration 是加速上傳。

👉 跨 Region 容錯移轉 -> Route 53、Global Accelerator。

**24.** 答案：**C**

依比例（20／80）分配流量，是加權路由。
易混淆：地理位置路由是依使用者所在地區；延遲路由是依延遲；容錯移轉路由是主要異常才切到備援。

👉 Route 53 常考的路由政策：Simple、Weighted（比例）、Latency（延遲）、Failover（主備）、Geolocation（地區）。

## 四、評估工具的層級對照

**25.** 答案：**C**

檢查帳戶現有資源的成本、安全、容錯、效能與服務配額，是 Trusted Advisor。
易混淆：CAF 和 Well-Architected Tool 看的是組織與架構，不是逐項掃描現有資源；AWS Config 記錄資源組態變化與合規，不提供這類整合建議。

👉 現有資源的檢查建議 -> Trusted Advisor。

**26.** 答案：**B**

組織上雲的準備度、人員與流程缺口，是 CAF 的範圍。
易混淆：Trusted Advisor 看不到人員技能與組織流程；AWS Organizations 是管理多帳戶與合併帳單。

👉 組織轉型、準備度 -> CAF。

**27.** 答案：**D**

單一工作負載的架構檢視與改善建議，是 Well-Architected Tool。
易混淆：CAF 是組織層級；Trusted Advisor 是資源層級。

👉 組織 -> CAF；資源 -> Trusted Advisor；工作負載架構 -> Well-Architected Tool。

**28.** 答案：**D**

根據歷史使用率指標找出過大或過小的資源並建議規格，是 Compute Optimizer。
易混淆：Cost Explorer 是檢視與分析過去的成本，Budgets 是設定預算與告警，都不會給規格建議。

👉 rightsizing、使用率偏低 -> Compute Optimizer。

## 五、單一用途服務

**29.** 答案：**A**

用自然語言搜尋企業內部文件並得到答案，是 Kendra（ML 驅動的企業搜尋）。
易混淆：Athena 是對 S3 資料下 SQL；Comprehend 是文字分析（情緒、實體）；Macie 是找敏感資料。

👉 自然語言搜尋文件 -> Kendra。

**30.** 答案：**D**

對 S3 的資料直接下標準 SQL、不需佈建伺服器，是 Athena。
易混淆：Redshift 要建立叢集，用於大型資料倉儲；Glue 是 ETL 與資料目錄。

👉 S3 + SQL + 無伺服器 -> Athena。

**31.** 答案：**C**

掃描 S3 找出 PII 等敏感資料，是 Macie。
易混淆：GuardDuty 偵測威脅與異常活動；Inspector 掃描漏洞；Secrets Manager 存放與輪替憑證。

👉 S3 敏感資料保護 -> Macie。

**32.** 答案：**B**

文字轉語音是 Polly。
易混淆：Transcribe 方向相反（語音轉文字）；Translate 是文字翻譯；Lex 是建立對話機器人。

👉 文字 -> 語音：Polly；語音 -> 文字：Transcribe。

**33.** 答案：**D**

通話錄音轉逐字稿，是 Transcribe。
易混淆：Polly 是反方向；Comprehend 是分析文字內容，需要先有文字；Rekognition 是影像與影片分析。

👉 語音 -> 文字 -> Transcribe。

**34.** 答案：**B**

持續分析 CloudTrail、VPC Flow Logs、DNS 紀錄來偵測威脅，是 GuardDuty。
易混淆：Inspector 掃描 EC2、容器、Lambda 的軟體漏洞；Macie 看 S3 敏感資料；Config 記錄資源組態。

👉 異常活動、威脅偵測 -> GuardDuty；漏洞掃描 -> Inspector。

## 六、已穩定主題的抽查

**35.** 答案：**C**

存取模式不固定、不想自己管理生命週期，是 Intelligent-Tiering，它會依存取模式自動搬移。
易混淆：Standard-IA 與 One Zone-IA 適合不常存取、但模式相對固定的資料；Deep Archive 是長期封存，取回要數小時。

👉 存取模式不明或變動 -> Intelligent-Tiering。

**36.** 答案：**D**

很少存取、需要毫秒取回、儲存成本盡量低，是 Glacier Instant Retrieval。
易混淆：Flexible Retrieval 與 Deep Archive 取回要分鐘到數小時；Standard-IA 也是毫秒，但儲存費比 Instant Retrieval 高，適合比較常存取（約每月）的資料。

👉 封存 + 毫秒取回 -> Glacier Instant Retrieval。

**37.** 答案：**A**

已有外部 IdP、員工單一登入並存取多個 AWS 帳戶，是 IAM Identity Center。
易混淆：Cognito 是給應用程式的終端使用者登入；IAM 使用者要逐一建立帳號，違反「不要第二組帳密」的需求；IAM Role 是給服務或臨時授權的身分。

👉 員工 SSO、既有 IdP、多帳戶 -> IAM Identity Center；App 使用者 -> Cognito。

**38.** 答案：**AC**

資料傳入 AWS 免費；同一個 AZ 內透過私有 IP 傳輸也免費。
易混淆：傳出到網際網路、跨 AZ、跨 Region 都會收費，其中跨 AZ 最容易被忘記。

👉 傳入免費；同 AZ 私有 IP 免費；傳出、跨 AZ、跨 Region 要收費。
