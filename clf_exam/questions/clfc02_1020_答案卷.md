## 詳解

## D05 帳號安全、IAM 與成本控制（18 題）

**1.** 答案：**A**

「全球部署」要的是多個 Region；Multi-AZ 還在同一個地理區域裡，解的是機房掛掉，不是離全球使用者近。

> 出處：D05 · 題庫第 0341 題

**2.** 答案：**C**

「資料必須留在本地、AWS 與公司資源低延遲」是把 AWS 機櫃搬進你機房，那是 Outposts；Local Zones 跟 Wavelength 都還是 AWS 的地點。

> 出處：D05 · 題庫第 0360 題

**3.** 答案：**A**

從網際網路「進來」AWS 不收費，出去要錢，Region 之間、AZ 之間的傳輸也要錢；這題順便記：跨 AZ 不是免費的，第 6 課成本會再看到。

> 出處：D05 · 題庫第 0186 題

**4.** 答案：**BE**

個別 User 才能追責，Group 才能一次調整一群人的權限，這是教材的 Group 那一段；A 共用金鑰無法追責，C 內嵌政策不能重用，D 違反最小權限。

> 出處：D05 · 題庫第 0539 題

**5.** 答案：**AE**

A 是最小權限，E 是密碼政策的基本項；B 分享 root 憑證是最嚴重的錯，C 直接給管理員群組違反最小權限，D 不讓改密碼反而降低安全。

> 出處：D05 · 題庫第 0106 題

**6.** 答案：**C**

跟上一題同一個工具，訊號詞是「最簡單」：一鍵下載 CSV；A 給稽核員管理員權限是反面選項，B 截圖是人工，D Trusted Advisor 只做檢查不列憑證。

> 出處：D05 · 題庫第 0288 題

**7.** 答案：**D**

「建立新帳戶、把帳戶分組、對群組套用政策」是 Organizations 的三個動作；IAM 管的是身分跟資源的存取權限，建帳戶、分組、套組織政策不是 它的工作。

> 出處：D05 · 題庫第 0122 題

**8.** 答案：**BE**

「只用 CLI 與 SDK」對應「只給程式化存取」，「只碰 RDS」對應一份只含 RDS 的 policy；D 管理員權限違反最小權限。注意題庫的正解還是建 IAM User，2026 年的 實務會優先用 Identity Center 的短期憑證，教材講過新舊並存，考試照題庫答。

> 出處：D05 · 題庫第 0428 題

**9.** 答案：**C**

「單一組憑證進多個 AWS 帳戶」是 Identity Center 的定義句；Organizations 管帳戶結構不管登入，IAM user 只活在一個帳戶，Control Tower 是建 多帳戶環境的工具。

> 出處：D05 · 題庫第 0339 題

**10.** 答案：**B**

「一個入口網站、指派的 AWS 帳戶加雲端應用、還管 SaaS」是 Identity Center 的存取入口；IAM 沒有入口網站，Directory Service 是 Active Directory 本身。

> 出處：D05 · 題庫第 0595 題

**11.** 答案：**C**

「支援創新、持續改善流程與程序」還是營運卓越；可靠性講的是從失敗中復原，不是流程改善。

> 出處：D05 · 題庫第 0404 題

**12.** 答案：**AC**

可靠性的設計原則：自動從失敗復原、停止猜測容量；B 把配額開給所有人是反面，D 單一 AZ 違反可靠性，E 次要 Region 的配額不是原則。

> 出處：D05 · 題庫第 0559 題

**13.** 答案：**C**

「運算資源的結構化與精簡分配」講的是用對資源、不浪費效能，是效能效率；成本優化講的是錢，題目沒提錢。

> 出處：D05 · 題庫第 0386 題

**14.** 答案：**A**

「評估遷移準備度」是 Cloud Adoption Framework 的用途，它是給組織上雲用的，Well-Architected 是給架構評分用的，兩個名字長得 像，題目就考這個區分。

> 出處：D05 · 題庫第 0178 題

**15.** 答案：**C**

「把支出與使用量隨時間視覺化」是 Cost Explorer，教材的「事後看」；Pricing Calculator 是還沒花錢的估算。

> 出處：D05 · 題庫第 0013 題

**16.** 答案：**B**

「兩個帳戶的帳單合併」是 Organizations 的合併帳單功能；Cost Explorer 只看不合併。

> 出處：D05 · 題庫第 0260 題

**17.** 答案：**B**

「根據歷史使用資料建議 EC2 該開多大」是 Compute Optimizer；Pricing Calculator 沒有歷史資料。

> 出處：D05 · 題庫第 0682 題

**18.** 答案：**C**

題目多加了「不需額外費用」：Cost Explorer 內建的 rightsizing 建議免費，Compute Optimizer 也免費但這題選項沒有它；WellArchitected Tool 是問卷，CloudWatch 是指標。

> 出處：D05 · 題庫第 0331 題

## D06 EC2 與運算選型（11 題）

**19.** 答案：**B**

「CPU 密集」直接對運算優化型，也就是 c 家族；記憶體密集才選 r。

> 出處：D06 · 題庫第 0444 題

**20.** 答案：**BC**

rightsize 是「依實際用量選大小」：看歷史使用率選機型、把冷資料移到便宜儲存層；A 換資料庫種類、D Multi-AZ 是可靠性、E 換部署方式，都不是調大小。

> 出處：D06 · 題庫第 0183 題

**21.** 答案：**B**

「測試開發、大數據平行運算、可容忍停機」三個訊號詞都指 Spot；Savings Plans 是承諾金額換折扣，跟能不能中斷無關。

> 出處：D06 · 題庫第 0565 題

**22.** 答案：**D**

「一年、全年無休、已正確規模化」代表不會換機型，Standard RI 折扣最深；Convertible 多付錢買一個用不到的彈性，Spot 會被收 回，資料庫不能接受。

> 出處：D06 · 題庫第 0254 題

**23.** 答案：**C**

「每插槽、每核心、每 VM 的既有授權」要看得到實體核心，只有 Dedicated Hosts；Dedicated Instances 只保證不跟別人共用硬體， 看不到插槽。

> 出處：D06 · 題庫第 0362 題

**24.** 答案：**D**

「應用程式要留在本地」不是定價題，是 Outposts；Dedicated Instances 還是在 AWS 機房。這題跟第 5 單元第 1 課的 360、651 是同 一個模式。

> 出處：D06 · 題庫第 0714 題

**25.** 答案：**D**

「控制單一執行個體的進出、不影響同子網路其他機器」還是 Security Group，因為它掛在機器上；Network ACL 掛在子網路，一改全 子網路都受影響。

> 出處：D06 · 題庫第 0554 題

**26.** 答案：**CE**

AWS 負責實體設施跟底層基礎架構的修補；設定 IAM、設定 SG、修補你機器上的應用程式都是客戶的事，這三個正好都是這個單元教過的。

> 出處：D06 · 題庫第 0610 題

**27.** 答案：**A**

「SQL 注入」是第七層的攻擊內容，SG 跟 NACL 只看 IP 跟埠，看不懂 HTTP 內容，要 WAF；A07 會講 WAF 掛在 CloudFront 或 ALB 前 面。

> 出處：D06 · 題庫第 0713 題

**28.** 答案：**D**

「自動增減 EC2、動態因應負載」是 Auto Scaling，A04 的主題；它靠的正是這一課的 Launch Template 跟 Golden AMI，機器才能在幾 十秒內開好。

> 出處：D06 · 題庫第 0157 題

**29.** 答案：**A**

「用指令碼快速佈建與管理 AWS 服務」是 AWS CLI；Session Manager 是連進機器的 shell，不是管 AWS 資源的工具，題目故意放在一 起。

> 出處：D06 · 題庫第 0303 題

## D07 儲存 EBS、EFS 與 S3（22 題）

**30.** 答案：**C**

「一次性備份、營運最有效率」就是拍 Snapshot，一個動作；A 自己複製、D 寫腳本都是手工，B 更離譜。

> 出處：D07 · 題庫第 0593 題

**31.** 答案：**C**

EBS 加密的金鑰由 KMS 管，教材第二段講過；Certificate Manager 管憑證，Systems Manager 管機器，Config 管設定合規。

> 出處：D07 · 題庫第 0074 題

**32.** 答案：**B**

「暫時性、機器停止或終止就刪」是 Instance Store 的定義句，教材第一段特別點過；EBS、EFS、S3 都獨立於機器存在。

> 出處：D07 · 題庫第 0311 題

**33.** 答案：**D**

「受管的 NFS 檔案系統」還是 EFS；Tape Gateway 是虛擬磁帶，Glacier 是冷儲存，EBS 是單機磁碟。

> 出處：D07 · 題庫第 0625 題

**34.** 答案：**C**

訊號詞「SMB 協定」直接指向 FSx for Windows File Server；EFS 是 NFS，S3 走 HTTP，EBS 不共享。

> 出處：D07 · 題庫第 0196 題

**35.** 答案：**D**

「本地的 NFS 工作負載搬上雲」選 Storage Gateway 的 S3 File Gateway，用 NFS 或 SMB 把檔案寫進 S3；Tape 是虛擬磁帶，Volume Gateway 把遠端儲存呈現成一顆磁 碟（走 iSCSI 這種區塊協定），不是檔案存取；FSx File Gateway 是給 Windows 檔案伺服器的。

> 出處：D07 · 題庫第 0110 題

**36.** 答案：**C**

第三次同一個答案：「用 NFS 這類協定在 S3 存取物件」是 Storage Gateway 的 file gateway；EFS 本身不是放 S3 裡的東西。三題連看 就知道題庫多愛考它。

> 出處：D07 · 題庫第 0533 題

**37.** 答案：**B**

四個選項是四種儲存的定義：A 區塊儲存是 EBS，C 的 SMB 是 FSx for Windows，D 的 NFS 是 EFS，只有 B 是物件儲存。

> 出處：D07 · 題庫第 0179 題

**38.** 答案：**D**

「使用者用公開 URL 直接下載」只有 S3 能做，每個物件本來就有網址；EBS、EFS 都得先有一台機器。教材第 5 課會補：實務上不開公開，改用 Presigned URL。

> 出處：D07 · 題庫第 0450 題

**39.** 答案：**D**

S3 總容量實質無限，你要記的上限是單一物件的大小，不是桶的總量。

> 出處：D07 · 題庫第 0658 題

**40.** 答案：**B**

「避免意外刪除或覆寫」是版本控制的用途，刪除只是蓋標記；Lifecycle 是搬跟刪，bucket policy 管誰能進來，加密管看不看得懂。

> 出處：D07 · 題庫第 0018 題

**41.** 答案：**B**

「不常存取、12 小時內取回、每 GB 最省」：Standard-IA 跟 One Zone-IA 都比 Glacier 貴，Flexible 的 Bulk 取回在 12 小時內，所以選它；選項裡沒有 Deep Archive，有的 話它的 Standard 取回也在 12 小時內，題目會再加「成本最低」來分。

> 出處：D07 · 題庫第 0201 題

**42.** 答案：**D**

「存取模式未知」是 Intelligent-Tiering 的定義句，讓它自己看多久沒碰就搬。

> 出處：D07 · 題庫第 0294 題

**43.** 答案：**C**

Intelligent-Tiering 做的事就是依存取模式自動在層之間搬物件；D 講的是 Glacier Deep Archive。

> 出處：D07 · 題庫第 0349 題

**44.** 答案：**B**

「一年看兩次、最低成本」：選項裡沒有 Deep Archive 跟 Flexible，Glacier Instant Retrieval 是有的裡面最便宜的，而且稽核要看時毫秒 就拿到；教材立場是如果選項有 Deep Archive 且能等 12 小時，那才是最低。

> 出處：D07 · 題庫第 0446 題

**45.** 答案：**AB**

選項裡能保護 S3 物件靜態資料的只有伺服器端加密的 SSE-S3 跟 SSE-KMS（教材還講了 DSSE-KMS，這題沒給）；TLS 跟 SSL 是傳輸中加密，TDE 是資料庫的透明 加密，跟 S3 無關。

> 出處：D07 · 題庫第 0219 題

**46.** 答案：**C**

「找出 S3 桶或 IAM Role 有沒有分享給外部」是 IAM Access Analyzer 的功能；Service Catalog 管產品目錄，Organizations 管帳戶。

> 出處：D07 · 題庫第 0036 題

**47.** 答案：**D**

「找出跟其他 AWS 帳戶共用的桶」還是 IAM Access Analyzer，三題連考；credential report 列的是使用者憑證，不是桶。

> 出處：D07 · 題庫第 0165 題

**48.** 答案：**B**

「自動辨識並分類敏感資料或智慧財產」還是 Macie；Inspector 掃機器的漏洞，Shield 擋 DDoS。

> 出處：D07 · 題庫第 0159 題

**49.** 答案：**A**

「在 S3 的文件裡搜尋文字內容」是 Kendra，企業搜尋服務，跟 RAG 的檢索是表親；Rekognition 看圖，Polly 念字，Lex 做聊天機器 人。

> 出處：D07 · 題庫第 0320 題

**50.** 答案：**B**

「讀所有 CSV 產彙總報告、營運負擔最小」還是 Athena；S3 Select 一次只查一個物件，不能跨檔彙總。

> 出處：D07 · 題庫第 0318 題

**51.** 答案：**B**

「用程式語言探索分析 S3 的資料」題庫還是選 Athena，因為 SQL 也算；SageMaker 是機器學習平台，題目沒提訓練模型。這題有點模 糊，考試照題庫答。

> 出處：D07 · 題庫第 0683 題

## D08 高可用與自動擴展（15 題）

**52.** 答案：**C**

「元件故障仍能維持運作」的最佳實務是自動容錯移轉到健康的資源，這正是負載平衡器只送健康目標、加上 Auto Scaling 群組（第 4 課會講，負責維持指定的 EC2 台 數）補機的組合；D 單一 EC2 就是單點失敗，B 放在特定 Region 跟容錯無關。

> 出處：D08 · 題庫第 0531 題

**53.** 答案：**D**

「把相依元件之間的故障隔離」是鬆耦合的定義；A 單體跟 C 設計單點都是反面，B 自動化是另一個原則。

> 出處：D08 · 題庫第 0371 題

**54.** 答案：**B**

ELB 的好處是在多個運算資源之間分配流量；A 講的增減後端 EC2 台數是 Auto Scaling 的事，ELB 只會自動擴展自己的負載平衡容量、不動你的機器；C 一個 ELB 只活在 一個 Region，跨 Region 要靠 Route 53 用 DNS 回覆導流，或 Global Accelerator 用全球固定入口導流，第 3 課會提。

> 出處：D08 · 題庫第 0621 題

**55.** 答案：**A**

「在託管網站的多台 EC2 之間分配流量」還是 ALB；WAF 是擋攻擊、CloudHSM 是金鑰硬體、Direct Connect 是專線。

> 出處：D08 · 題庫第 0542 題

**56.** 答案：**B**

WAF 規則部署在第七層的入口，選項裡只有 ALB 是第七層；NLB 是第四層看不懂 HTTP，所以掛不了 WAF。

> 出處：D08 · 題庫第 0425 題

**57.** 答案：**A**

「多個 Region 部署、要提升效能與可用性」還是 Global Accelerator；Auto Scaling 只在一個 Region 裡調台數。

> 出處：D08 · 題庫第 0663 題

**58.** 答案：**A**

ASG 的擴展方式是依需求自動增減 EC2 的台數；C「調整實例大小」是垂直擴展，ASG 不做，B 沒有 serverless 的 EC2 這種東西。

> 出處：D08 · 題庫第 0209 題

**59.** 答案：**C**

「依當前負載自動調整 EC2 台數」選 Auto Scaling 群組；專用主機是給你專用的實體伺服器，預留實例是承諾用量換折扣，放置群組管 機器擺在哪，三個都不會依負載增減台數。

> 出處：D08 · 題庫第 0465 題

**60.** 答案：**B**

「一天只有特定時段有人用、要最低營運成本」選 Auto Scaling 群組，時段外縮回去；A 多 AZ 是可用性不是成本，D 私有子網路跟成本無關。

> 出處：D08 · 題庫第 0555 題

**61.** 答案：**BE**

彈性的兩個面向：隨需求調整資源規模、需要時能輕鬆佈建；A 重啟速度、C 最大 RAM 是機器規格，D 隨用隨付是計費模式不是彈性本身。

> 出處：D08 · 題庫第 0040 題

**62.** 答案：**D**

「按需部署、不需要時釋放」是彈性的定義句；高可用著重減少停機，韌性講從故障恢復，解耦著重降低元件相依與故障的連帶影響。

> 出處：D08 · 題庫第 0347 題

**63.** 答案：**B**

第三次同一個定義，還是 Elasticity；可用性、耐久性、可靠性都不是講台數會動。

> 出處：D08 · 題庫第 0638 題

**64.** 答案：**B**

「依負載上下調整規模」對應的雲端優勢是「不用再猜容量」，因為容量會跟著負載動；A 全球部署、C 規模經濟、D 固定成本換可變成本都是另外三個優勢。

> 出處：D08 · 題庫第 0540 題

**65.** 答案：**B**

「無狀態、容錯、可中斷」三個訊號詞都指 Spot，向量化批次正是這個形狀；關鍵是工作能容忍中斷，Reserved 是承諾用量換折扣，題 目沒有給長期穩定用量的線索。

> 出處：D08 · 題庫第 0033 題

**66.** 答案：**D**

「受管服務自動配置容量、負載平衡、擴展、健康監控」正是 Elastic Beanstalk 提供的整套，它把 A04 整個單元打包成一個服務；ECS 跟 EKS 是容器平台，題目說非容器 化；Lambda 是函式執行環境，不是題目要的網頁應用部署整套。

> 出處：D08 · 題庫第 0397 題

## D09 VPC 網路（12 題）

**67.** 答案：**AC**

兩道防火牆的規則都能用 CIDR 指定 IP 範圍：Security Group 跟 Network ACL；AMI、Budgets、EBS 跟 IP 範圍無關。

> 出處：D09 · 題庫第 0614 題

**68.** 答案：**A**

「允許來自網際網路的入站流量」只有 Internet gateway；NAT gateway 只讓裡面主動連出去並收回應，不接受外面主動建立的新連線， 這題就是考這個分界。

> 出處：D09 · 題庫第 0352 題

**69.** 答案：**AC**

把地端網路接到 VPC 的兩條路：一般的 VPN 在網際網路上加密傳輸，Direct Connect 是實體專線；VPC peering 是 VPC 對 VPC，ELB 跟 CloudFront 不是網路連線。

> 出處：D09 · 題庫第 0181 題

**70.** 答案：**B**

「把 VPC 跟內部網路接到一個中央樞紐」是 Transit Gateway 的定義句；Virtual private gateway 掛在單一 VPC 上，Customer gateway 代表客戶端那台設備的設定，兩個都不是中央轉送樞紐。

> 出處：D09 · 題庫第 0443 題

**71.** 答案：**B**

「私有子網路主動出網下載更新、同時不讓網際網路連進來」是 NAT gateway 的定義；VPC endpoint 跟 PrivateLink 是通往指定服務的 私有入口，不是任意上網的出口；VPC peering 是去別的 VPC。

> 出處：D09 · 題庫第 0199 題

**72.** 答案：**AD**

NACL 兩個特性：無狀態、依編號從小到大處理比中就停；B 有狀態跟 E 執行個體層級講的是 Security Group，C「評估所有規則」也是 Security Group 的做法。

> 出處：D09 · 題庫第 0291 題

**73.** 答案：**B**

第三次：子網路層級的防火牆是 Network ACL；Traffic Mirroring 是複製流量拿去分析，Internet gateway 是大門不是防火牆。

> 出處：D09 · 題庫第 0493 題

**74.** 答案：**C**

「無狀態的網路過濾」是 NACL；Security Group 是有狀態的，PrivateLink 是私有連線，WAF 在第七層。

> 出處：D09 · 題庫第 0665 題

**75.** 答案：**A**

「找出對特定埠不設限的 Security Group」是 Trusted Advisor 的安全檢查項目；CloudWatch 看指標，GuardDuty 偵測威脅行為， Health Dashboard 看 AWS 服務本身的狀態。

> 出處：D09 · 題庫第 0065 題

**76.** 答案：**B**

「VPC 跟 AWS 服務私下連線、流量不暴露在公網」是 PrivateLink，介面型端點底下就是它；Internet Gateway 正好相反，Inspector 掃 漏洞，Amazon Connect 是客服中心。

> 出處：D09 · 題庫第 0715 題

**77.** 答案：**C**

「VPC 裡網路介面的入站與出站流量日誌」是 VPC Flow Logs；CloudTrail 記的是誰呼叫了哪個 API，不是封包；CloudWatch Logs 只是 Flow Logs 可以送去存的地方。

> 出處：D09 · 題庫第 0119 題

**78.** 答案：**A**

第三次 VPC Flow Logs；路由表決定封包往哪走但不留紀錄，CloudTrail 記 API 呼叫。除錯時兩個都會用：CloudTrail 查「誰改了設 定」，Flow Logs 查流量被接受還是被拒絕，再配合設定或 Reachability Analyzer 找出是哪個元件擋的。

> 出處：D09 · 題庫第 0310 題

## D10 資料庫 RDS、Aurora 與快取（11 題）

**79.** 答案：**B**

「關聯式、受管、自動安裝並定期更新軟體」是 RDS；EBS 是磁碟不是資料庫，DynamoDB 是 NoSQL，S3 是物件儲存。

> 出處：D10 · 題庫第 0587 題

**80.** 答案：**C**

「不想管硬體、可用性、複寫」三件事，就是第 1 課 RDS 替你做掉的事；A、B 都是自己養，D 是快取不是關聯式資料庫。

> 出處：D10 · 題庫第 0322 題

**81.** 答案：**C**

RDS 的自動備份是 AWS 替你做的；A 是 EC2 的作業系統修補，屬客戶；B、D 是客戶自己的業務與成本。

> 出處：D10 · 題庫第 0592 題

**82.** 答案：**A**

MariaDB 是 RDS 支援的引擎之一，搬過去維運負擔最低；Neptune 是圖形資料庫，DynamoDB 是 NoSQL，S3 是物件儲存。

> 出處：D10 · 題庫第 0503 題

**83.** 答案：**C**

「同步複寫到另一個 AZ」是 Multi-AZ 的定義；讀取複本是非同步，這一字之差就是第 2 課的重點。

> 出處：D10 · 題庫第 0411 題

**84.** 答案：**C**

高可用加容錯，就是跨多個 AZ 的 RDS，也就是 Multi-AZ；單一 AZ 沒有備援，快照要手動還原，DMS 是搬資料的工具。

> 出處：D10 · 題庫第 0525 題

**85.** 答案：**D**

全受管又相容 MySQL 的是 Aurora；Redshift 是資料倉儲，DynamoDB 是 NoSQL。

> 出處：D10 · 題庫第 0061 題

**86.** 答案：**BE**

受管且能跑 PostgreSQL 的是 RDS 與 Aurora；EC2 也能跑但不是受管，Athena 是查 S3 的查詢服務。

> 出處：D10 · 題庫第 0190 題

**87.** 答案：**D**

「不常使用」加「管理負擔最低」，選 Aurora Serverless，依用量調整容量、閒置可以縮到最小甚至暫停；B、C 要自己挑固定的機型。

> 出處：D10 · 題庫第 0240 題

**88.** 答案：**B**

安全儲存並加密資料庫密碼選 Secrets Manager；IAM 管的是 AWS 身分，Cognito 管的是你的應用程式使用者。

> 出處：D10 · 題庫第 0217 題

**89.** 答案：**B**

資料庫憑證輪替排程、營運負擔最低，選 Secrets Manager，它內建 RDS 的輪替；Systems Manager 是維運工具箱，要自己組。

> 出處：D10 · 題庫第 0072 題

## D11 DNS 與內容分發（11 題）

**90.** 答案：**B**

「在 AWS 上託管網站的網域名稱」是 Route 53 的 DNS 服務，也就是第 1 課的託管區域；CloudFront 只分發內容不管網域解析， Lambda 跑程式，Direct Connect 是專線。

> 出處：D11 · 題庫第 0476 題

**91.** 答案：**C**

「提供 DNS 解析功能」的服務是 Route 53；CloudFront 常被拿來誘答，它靠 DNS 把使用者導到邊緣位置，但自己不是 DNS 服務。題幹 措辭有點鬆：VPC 內建的 DNS 伺服器背後就是 Route 53 Resolver，所以嚴格說 B 也沾得上邊，但考試要的是服務名稱 Route 53。

> 出處：D11 · 題庫第 0528 題

**92.** 答案：**A**

「某個地理區域發生天災仍能運作」要跨 Region 部署；B 與 C 講的 CloudFront 位置與邊緣位置是快取點，不能跑 EC2；D 的 Local Zones 是某個 Region 往外延伸 出去的小據點，不是另一個獨立的 Region，放進去不算跨區域部署。本課的 Route 53 故障切換就是把使用者從掛掉的區域切到另一個區域的工具。

> 出處：D11 · 題庫第 0147 題

**93.** 答案：**A**

「部署在接近終端使用者的位置」是邊緣位置，CloudFront 用的就是它。題幹的「部署應用程式」不是把 EC2 那種後端程式搬到邊緣去 跑，是把應用程式對外的內容與回應快取到邊緣，使用者就近拿到，這是 CloudFront 語境裡「靠近使用者」的意思；Route 53 是 DNS， Auto Scaling 是調機器數量，AppSync 是 GraphQL API 服務。

> 出處：D11 · 題庫第 0085 題

**94.** 答案：**C**

「用 edge location 快取內容」就是 CloudFront 的定義；Route 53 也用邊緣位置但做的是 DNS 回應不是快取內容，Kinesis 與 SQS 跟邊 緣無關。

> 出處：D11 · 題庫第 0643 題

**95.** 答案：**C**

網站在 EC2 上要給全球使用者最低延遲，把 EC2 設成 CloudFront 的來源；A 的邊緣位置不能跑 EC2；B 的「不同區域但相同可用區」在邏輯上不成立，可用區屬於 單一 Region；D 是換帳戶不換地點，對全球使用者的延遲毫無幫助。

> 出處：D11 · 題庫第 0269 題

**96.** 答案：**B**

第三次同型題，關鍵詞「全球使用者、低延遲回應時間」選 CloudFront；CloudFormation 是基礎設施即程式碼、ElastiCache 是資料庫 前面的記憶體快取（第 10 單元）、DynamoDB 是 NoSQL 資料庫，都不是把內容送到使用者附近。

> 出處：D11 · 題庫第 0597 題

**97.** 答案：**A**

「多個公開應用程式在 ALB 後方、要提升效能」選 Global Accelerator，它的端點就包括 ALB，把使用者的連線從最近的邊緣位置走 AWS 骨幹送過來；ElastiCache 快取的是資料庫查詢不是網路路徑，Amazon Connect 是客服中心，CloudWatch 是監控。

> 出處：D11 · 題庫第 0707 題

**98.** 答案：**B**

「維持頻寬吞吐量、比公用網際網路更一致的體驗」講的是地端到 AWS 的專線 Direct Connect；CloudFront 是給終端使用者的內容分 發，放在選項裡是混淆用，一般的 Site-to-Site VPN 正是在公用網際網路上加密，Amazon Connect 是客服中心。

> 出處：D11 · 題庫第 0547 題

**99.** 答案：**B**

靠區域、可用區、邊緣位置把應用部署給全球使用者，這項雲端優勢叫全球覆蓋（Global reach）；規模經濟講的是價格、敏捷性講的是 快速取得資源、高可用講的是不中斷，都不是「到全球」這件事。

> 出處：D11 · 題庫第 0372 題

**100.** 答案：**D**

為 IAM 使用者實作 MFA 是客戶的；A 的 S3 基礎設施裝置修補、B 的資料中心實體安全、C 的 Lambda@Edge 作業系統更新都是 AWS 的責任，Lambda@Edge 是在邊緣位置跑程式的服務，底層機器 AWS 顧。

> 出處：D11 · 題庫第 0648 題
