## 一、型態與用量：五項功能有一項要用，就選 REST

**三件事**

- API Gateway 是 Lambda 前面的 API 入口
- REST API 功能多、HTTP API 價格低
- API 金鑰與用量計畫只有 REST API 有

**五項只有 REST 才有的功能**

| 功能                           | REST API | HTTP API |
| ------------------------------ | -------- | -------- |
| API 金鑰（識別客戶）           | 有       | 無       |
| 每客戶限流                     | 有       | 無       |
| 請求驗證（檢查請求格式對不對） | 有       | 無       |
| AWS WAF（擋惡意請求）          | 有       | 無       |
| 私有端點（只從私有網路進來）   | 有       | 無       |

- 任何一項是需求，就選 REST；都不需要才選 HTTP API

**用量計畫：金鑰識別客戶，速率與配額管用量**

| 元件     | 做什麼                                       |
| -------- | -------------------------------------------- |
| API 金鑰 | 識別是哪個客戶                               |
| 用量計畫 | 設定速率、突發、配額；金鑰屬於用量計畫       |
| REST API | 被用量計畫管；超過可能收到 `429`（請求太多） |

- **限流與配額只是目標；API 金鑰不是認證**

**CCP 考點**

- 防 SQL 注入、擋惡意 HTTP 請求 → **AWS WAF**；Network ACL、Security Group、ACM 是誘答（題庫 CLF-C02 2026Q3 第 0124 題）
- 講義註記：題庫沒有 API Gateway 專題題，這題取最貼近者；WAF 是只有 REST 才有的功能之一

> 一句話：五項功能有一項要用選 REST，用不到選 HTTP。用量計畫只是目標；成本用 AWS Budgets 盯，請求用 WAF 管。

## 二、代理整合：整包交給函式，回傳格式要對

**三件事**

- Gateway 把整個請求放進 `event`
- 函式自己解析、自己決定回什麼
- 回傳格式不符，閘道回 `502`

**Lambda proxy integration：Gateway 整包轉交，不改內容**

- Client 送出請求 → API Gateway 原樣轉交 → Lambda 收到 `event`
- `event` 含：標頭（headers）、查詢字串（`?` 後參數）、路徑變數（網址中的一段）、內容（body）

**輸出格式：`statusCode` 與 `body` 必給，格式錯就 502**

```json
{
  "statusCode": 200,
  "headers": { "Content-Type": "application/json" },
  "body": "{\"ok\": true}"
}
```

- **`body` 是字串**（所以裡面的 JSON 要先轉成字串）
- 其他格式 → `502 Bad Gateway`

**排查口訣：Lambda 成功、呼叫端卻看到 502，先查回傳格式**

**CCP 考點**

- Lambda 的共同責任模型：**函式的程式碼是客戶的責任**（回傳格式也在裡面）；硬體、作業系統修補歸 AWS（題庫第 0042 題）
- 講義註記：題庫沒有代理整合專題題，這題取最貼近者

> 一句話：Gateway 整包轉交，函式要回對格式。

## 三、認證授權：使用者集區認人，身分集區發憑證

**三件事**

- 認證問「你是誰」，授權決定「你能做什麼」
- Cognito 登入服務：User Pool 發權杖，Identity Pool 換憑證
- 授權器三種：Cognito、Lambda、IAM

**兩個集區：一個認人，一個發憑證**

| 問題              | 誰負責             | 流程                                             |
| ----------------- | ------------------ | ------------------------------------------------ |
| 進得了 API？      | User Pool + 授權器 | User Pool 認人、發權杖 → 授權器檢查 → 放行或擋下 |
| 碰得了 AWS 資源？ | Identity Pool      | 權杖換暫時憑證 → 拿憑證呼叫 S3、DynamoDB         |

**REST API 的三種擋法**

| 授權器  | 做法                   |
| ------- | ---------------------- |
| Cognito | 用使用者集區驗權杖     |
| Lambda  | 自己寫驗證函式         |
| IAM     | 用角色與政策管誰能呼叫 |

- 以上是 REST API 的三種做法；**HTTP API 用 JWT**

**CCP 考點**

- 使用者註冊、登入、行動與 Web 應用程式的身分驗證 → **Amazon Cognito**；Config、GuardDuty、Systems Manager 是誘答（題庫第 0509 題）

> 一句話：使用者集區認人，身分集區發憑證。進 API 看授權器，碰 AWS 看憑證。

## 四、跨域排查：curl 正常、瀏覽器失敗，先查回應標頭

**三件事**

- CORS 是**瀏覽器**的安全機制，命令列工具 curl 不檢查
- 網域、子網域、埠、協定**任一不同**都算跨域
- 非簡單請求先送 `OPTIONS` 預檢（先問可不可以）

**預檢流程：先問可不可以，再送真正請求**

| 順序 | 誰     | 做什麼             |
| ---- | ------ | ------------------ |
| ①    | 瀏覽器 | 送 `OPTIONS` 預檢  |
| ②    | 後端   | 回允許的來源       |
| ③    | 瀏覽器 | 後端同意才送真請求 |

- 後端不同意，真請求不會送出
- 預檢由誰回覆，依整合類型而定

**代理整合：三個 CORS 標頭由函式自己回**

```json
{
  "headers": {
    "Access-Control-Allow-Origin": "網址",
    "Access-Control-Allow-Methods": "方法",
    "Access-Control-Allow-Headers": "標頭"
  }
}
```

- 範例中的中文要換成真的值

**CCP 考點**

- 監控並阻擋 CloudFront 收到的惡意 HTTP／HTTPS 請求 → **AWS WAF**；GuardDuty（偵測威脅）、Inspector（弱點評估）、Detective（事後分析）是誘答（題庫第 0468 題）
- 講義註記：題庫沒有 CORS 專題題；題內 CloudFront 本課不教，只需看出 WAF 擋惡意請求

> 一句話：curl 正常、瀏覽器失敗，先查回應標頭。非簡單請求先預檢；代理整合的標頭函式自己回。

## 五、實作：補完一支帶認證的 REST API

流程：Client 帶權杖 → REST API → Cognito 授權器 → Lambda（增刪查改）。補三處：**函式、認證、部署到 `dev` 階段**（階段＝部署後的環境名字）。資料儲存依講師發的實作模板；講義未標區域與預期費用，動手前先向講師確認。

**必做：六步**

1. **補完 Lambda 程式**：增刪查改（新增、刪除、查詢、修改）；回傳格式照代理整合
2. **建 REST API 接函式**：`{proxy+}`＝子網址全交函式
3. **建使用者集區、授權器**：登入取得權杖
4. **授權器設到方法上**：**每個方法都要設**
5. **部署到 `dev` 階段**：記下呼叫網址
6. **有、無權杖各呼叫一次**：沒權杖的要被擋

**清理：做完全部刪掉，才不會留下帳單**

1. 刪 REST API
2. 刪使用者集區
3. 刪 Lambda 與執行角色
4. 刪模板建立的資料資源

- 刪之前看清楚名稱，只刪自己建的
