# lecture_notes 筆記撰寫規範

此規範由 `lecture_notes/` 內全部檔案（d04–d14 單元筆記、上課日誌、課堂補充）逐一掃描後歸納。**只管這個資料夾內的筆記**。

新增單元筆記前，先讀 `d13_iac.md`、`d11_dns_cdn.md`（新格式、最完整）與 `d10_rds.md`（CLAUDE.md 指定的格式參考）。`d04`–`d09` 是舊格式，只當內容風格參考，不當結構範本。

## 1. 檔案類型與命名

| 類型     | 檔名                              | 標題（H1）                                                         |
| -------- | --------------------------------- | ------------------------------------------------------------------ |
| 單元筆記 | `d{兩位數單元}_{英文小寫主題}.md` | `# dNN \| 主題名稱`（全部單元統一，例：`# d12 \| 可觀測性與稽核`） |
| 上課日誌 | `YYYYMMDD_上課日誌.md`            | `# YYYY-MM-DD \| 摘要：dXX 下半 + dYY 到某主題`                    |
| 零散補充 | `d00_課堂補充.md`（單一檔，往下追加） | `# d00 - 課堂補充`                                             |

- 單元編號 = 講義單元編號，對應 `lectures/DNN xxx.pdf`；主題用服務或概念縮寫（`iam`、`ec2`、`storage`、`ha`、`vpc`、`rds`、`dns_cdn`）。
- 職涯建議、延伸學習連結這類零碎內容追加到 `d00_課堂補充.md`，不另開新檔。

## 2. 兩代格式對照

|          | 舊格式（d04–d09）                         | 新格式（d10–d14，**新檔照這個**）                                           |
| -------- | ----------------------------------------- | --------------------------------------------------------------------------- |
| 骨架     | `[內容]` 與 `[作業]` 兩大段               | 概念章 → 實作 → 回家作業 → Takeaway，不用 `[內容]` 標記                     |
| 密度     | 長條列，一條塞多個分號句                  | 短條列，一行一個要點，多用表格                                              |
| 章節標題 | 名詞式（「三種儲存的形狀」）              | 結論／口號式（「快取放在門口，桶不用公開」「資料庫交給 AWS 養，再多一台」） |
| 章首     | 「六個詞先記起來」的一條長 bullet         | `**三件事**` 三條要點；d11 另有「六個名詞」表                               |
| 作業     | `[作業]` 下分「一、實作」「二、回家作業」 | `## 五、實作`、`## 六、回家作業`                                            |

## 3. 新格式骨架

```
# dNN | 主題名稱

> 來源：`lectures/DNN xxx.pdf`（共 N 頁；定價與額度為講義 YYYY-MM-DD 查閱的數字）

**今日目標**：一句話

**六個名詞**（表格：名詞｜意思）      ← 名詞多時才放

---

## 一、結論式標題
**三件事**
- …
（展開：表格、步驟、✗/✓ 框、指令、CCP 考點）

## 二、…  ## 三、…  ## 四、…       ← 概念章通常 3–4 章

## 五、實作：一句話描述成品
## 六、回家作業：都拿期末專題來做，一律個人完成(略，參考用)
## Takeaway                          ← 3–4 條，每條一句
```

- 章節用「一、二、三」中文編號；講義沒有的段落直接省略，不硬湊。
- 回家作業只列「題目標題＋一句說明」，標「(略，參考用)」，不代寫答案。

## 4. 寫作特色（逐項都是現有檔案反覆出現的）

**內容組織**

- **先講責任線／分界線**，再講細節（RDS：「責任線換了位置」；共同責任模型；Multi-AZ 保命 vs Read Replica 分擔）。
- **兩個以上選項一律做比較表**：欄位用「目的／代價／何時選」，不用段落描述。
- **「需求訊號詞 → 選什麼」表**：給考題速查（d10 的 Multi-AZ／Read Replica、d08 的 ALB／NLB）。
- **決策順序**用編號流程寫出（d06 定價：能否被中斷 → 用滿一年 → 授權綁核心 → On-Demand）。
- **排障順序**用分層表（d09 路由 → SG → NACL → NAT → 應用層），欄位含「檢查項」「沒配的徵狀」。
- **易混淆組**獨立標出（IAM Identity Center vs Cognito、CAF vs Well-Architected、Dedicated Instances vs Hosts vs Capacity Reservations、CloudFront vs Global Accelerator）。
- **數字要具體**（60～120 秒、18%、TTL 300、128 KB、最多 35 天），並標明出處是「講義」「老師估算」還是「官方」；後兩者不混為一談。

**固定元件**

- **迷思澄清框**（✗/✓）：

  ```
  **標題問句？**

  - ✗ 大家通常會想：…
  - ✓ 實際上：…
  ```

- **CCP 考點**：概念章末尾獨立一段 `**CCP 考點**`，格式「題目訊號詞 → 答案」，並點出誘答選項（「提供 DNS → Route 53，CloudFront 是誘答」）。
- **金句**：保留講義原話（「S3 是倉庫，向量索引是目錄」「加速不等於快取」），不改寫成自己的話。
- **口訣**：講義給的記憶法照錄（如 `E.P.A.R.C.`）。
- **指令區塊**：CLI／curl／dig 前加一行說明用途，並標費用（「CloudShell，0 元」）；整段註解寫在 code block 內。

**AI／Agent 應用段**

- d05–d14 多數單元都有一章把該主題套到 **LLM／Agent**（Agent 權限、GPU vs Bedrock、RAG 與 S3、LLM 服務的指標／逾時／健康檢查、Agent 出口網路、語義快取、CDN 與聊天 API）。講義有這章就寫，且保留「一般 Web 服務 vs LLM 服務」對照表。
- 回家作業圍繞同一個**期末專題**（Agent + Bedrock 的多層架構），題目措辭用「替專題…」。

**實作章**

- 開頭寫：全部在主控台或 CloudShell、使用的身分（`course-admin`）、區域（Tokyo／`ap-northeast-1`）、**預期費用與當天清理**。
- 分層：**必做 70%／進階 20%／加分 10%**（d09 為 60/20/20，以講義為準）；必做用編號步驟，每步粗體標動作名。
- 必含：卡關提示表（卡在哪｜怎麼辦）、清理順序（含「為什麼不能反」）、繳交清單（截圖數量＋一句對帳，並提醒「刪資源前先拍」）、驗收配分。
- 用「為什麼改成 v2 還是看到 v1」這類反直覺現象，補一小段原因說明。

## 5. 內容正確性

- 以講義為準，但**講義常有 OCR／簡繁混雜錯字**（d04 有「ㄐ」，d09 有「从」「內部只」，d10 有「⾨檻」「淺 20 對」「蛇形距離」等）。整理時修正明顯錯字；語意不確定的（如「蛇形距離」疑為「餘弦距離」）回頭對照 PDF，或標「待查證」，不猜。
- **不要複製殘留的編輯痕跡**：如 d04 內的「（修正：原…）」括號、`[內容]` 後面的空白佔位。
- 定價、額度、時間線寫**講義查閱日期**，不自行補未經確認的數字；與官方現況可能不符時加 `> 注意：…` 並建議查官方文件。
- **使用者的課堂補充**（`補充：` 條目、括號個人註記、老師口頭提點）保留在原章節，不潤飾掉。
- 筆記內不放帳號 ID、Access Key、密碼、真實 Endpoint。

## 6. 上課日誌格式

```
# YYYY-MM-DD | 摘要：dXX 下半 + dYY 到某主題

**dXX（子主題）**
- 3–6 條重點，每條一句

**補充**
- 老師口頭提點、考試重點（如「Standard → Standard IA → Glacier 的順序要背」）
```

只摘要當天重點，細節留給單元筆記。

## 7. 新增後的收尾（缺一不可）

1. 該筆記若在 `CLAUDE.md`「待辦提醒」清單中（如 `d15_xxx.md`），從清單移除。
2. 同步更新 `README.md` 的「待辦」區塊，並把新筆記加入檔案清單。
3. 確認 `lectures/` 有對應 PDF，來源行檔名與頁數正確。
4. 不自動 commit，使用者要求時才提交。
