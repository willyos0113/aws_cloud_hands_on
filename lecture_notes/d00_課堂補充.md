## d17 延伸：SQS 與 State Machine

> 非講義內容，細節以官方文件為準。

| 項目       | SQS                                                | State Machine（Step Functions）            |
| ---------- | -------------------------------------------------- | ------------------------------------------ |
| 角色       | 訊息緩衝（叫號機）                                 | 流程編排（辦事流程單）                     |
| **管什麼** | **併發**：請求同時湧入，先排隊、多個工作者並行消化 | **流程**：一次執行內，誰先誰後、分支、等待 |
| 解決       | 削峰、解耦、下游掛了不丟                           | 步驟順序、分支、失敗處理                   |
| 失敗       | 可見性逾時、死信佇列                               | `Retry`、`Catch`                           |
| 考題       | 傳訊、解耦                                         | 協調工作流程                               |

**怎麼組合**

```
訂單 → SQS → Lambda/Pipes → State Machine → 步驟 A → 步驟 B
                                  └─ 派工到 SQS ⇄ 工作者（.waitForTaskToken 等回報）
```

- 入口放 SQS 控速；流程中派工並暫停，等工作者回報 token
- 兩層都要設逾時與冪等，否則訊息進死信時流程會卡住
- 併發在 SQS：請求再多都先排隊，工作者數量決定同時處理幾則（SQS 不限制消費者數量；搭配 Lambda 可用 `maxConcurrency` 限速，細節查官方）
- 流程在 State Machine：每次執行各走各的步驟；它不負責吸收流量尖峰

> 一句話：**SQS 管併發（人多怎麼排），State Machine 管流程（事情怎麼走）**；訊息別丟靠 SQS，步驟別亂靠 State Machine。
